# Reassign PM

The current agent (`$PASEO_AGENT_ID`) becomes the project's PM. Run this only in the agent the owner asked to take over; never run it from `$handoff` or in the outgoing PM. Use supported Paseo tools or CLI/API operations. Reassignment authorizes archiving the one bound previous PM, not its workspace or unrelated agents.

Takeover is one-directional and claim-first, so two agents running it against each other cannot both proceed:

- **One direction.** The outgoing PM is older than self: its persisted `createdAt` is earlier, or equal with a smaller full ID (stable ordinal comparison). Never select, demote, or archive a PM created after self unless the owner named that exact ID as the old PM in this request. When an eligible same-project PM is newer than self, self is the stale side: report it and mutate nothing.
- **Bind once.** Discovery binds one transition: the project, the outgoing PM's full ID (or none), and self. Never reselect. If a later refresh shows the bound PM archived, relabeled by another agent, or replaced by a different PM, stop and report the observed state; never retarget another agent.
- **Claim first.** Moving the project's `role=pm` label to self (step 5) is the first mutation. Only the sole unarchived holder of that label may archive a PM, and only the bound outgoing PM after it no longer holds the label. A failed or contested claim blocks every later step; it never authorizes archiving or relabeling the competing agent.

1. **Discover and select automatically.** Inspect self and list agents across all workspaces, including dormant and archived PMs. With CLI, use `paseo ls --global --all --json`, then inspect full candidate IDs with `paseo inspect <id> --json`; use supported API snapshots for labels and workspace/project metadata omitted by CLI inspect. A cwd filter or recent-only result cannot prove absence. Confirm persisted archive state explicitly; an `idle` snapshot without an archive flag does not prove the agent is unarchived. Exclude `$PASEO_AGENT_ID` from every old-PM candidate set, even when self inherited `role=pm/project` labels from a copied chat.

   Resolve evidence in this order:

   - **Source.** Inspect an explicit owner old PM ID first; if that record cannot be verified, report the failed lookup and stop before mutation. When no explicit ID is supplied, identify the source of this fork/copy from available supported provenance or supplied old-chat context. Verify the full ID against a real PM record and its project; for a context header naming a title/directory, corroborate against the record and saved activity. Arbitrary IDs mentioned in historical transcripts, self's inherited labels, and a matching title alone are not source proof. Unverifiable provenance does not outrank eligible candidates.
   - **Project.** Use the supplied project first, then the verified source PM's project, then workspace/project metadata and existing path equivalence; the current directory basename is the fallback. Expand home paths and compare realpaths where available. Missing paths, conflicting project evidence, or differing labels remain unresolved evidence. Report that evidence and stop before mutation when it prevents confirming a single project; never invent another project target.
   - **Previous PM.** Eligible candidates are confirmed same-project, unarchived `role=pm` records other than self. Rank by parsed persisted `createdAt`, ordering equal timestamps by full ID ascending with a stable ordinal comparison; `updatedAt`, activity, quota, status, list position, and relative display times do not determine recency. Missing or invalid creation timestamps, self's included, that prevent ranking require an evidence report before mutation. A candidate newer than self stops the takeover (see One direction). Otherwise select the verified explicit owner old PM ID, else the verified source PM, else the newest candidate older than self. An explicit or verified source PM that is archived or no longer carries `role=pm` is never replaced by another candidate: if self is already the sole unarchived `role=pm/project=<name>` holder, this transition already completed, so report it and mutate nothing more; otherwise report the changed state and stop until the owner names the old PM. Only when no explicit or source PM was given and complete discovery finds no eligible candidate, continue without an archive.

   Announce the bound outgoing PM's full ID, project, and evidence (explicit owner ID, verified source, or creation timestamp and tie ordering), or announce that complete discovery found none. Multiple confirmed same-project PM matches older than self invoke this selection rule, not a question asking the owner to choose. Keep the other confirmed older candidates for label cleanup in step 7.
2. **Read before waking.** Resume from root `STATUS.html` and `LESSONS.md` with `repo-lessons`, and inspect the bound old PM's saved activity plus verified source context when different or archived. Request a live handoff only for information unavailable there and when the old PM has capacity. Exhausted quota never requires a live handoff and must not block an otherwise verified takeover. Do not write the pair before the claim in step 5: until then the outgoing PM is its writer. Preserve unrelated checkout changes.
3. **Inventory retained agents.** Identify workers and watchers from actual parent relationships, explicit workstream assignments, and saved activity. Sharing a cwd is insufficient. Record each retained agent's Paseo ID, workspace ID, provider/native session ID, exact model, mode/thinking/features, role labels, cwd, and lifecycle state. Include assigned agents in other workspaces; leave unrelated agents alone. Completed workers stay in place by default without a retention question; include them only when the owner explicitly requested it. Read each provider's model catalog and copy IDs verbatim, including Claude `[1m]` suffixes and OpenCode provider prefixes. Do not replace a model with a similar one when its ID is unavailable.
4. **Check placement before claiming.** Retained agents already in self's workspace need no move. For others, confirm read-only that a supported relocation operation preserves the recorded identities, native history, settings, roles, and usable cwd. A parent label changes ownership, not workspace membership. Do not plan replacement sessions, filesystem aliases, or daemon storage edits. If the installed version cannot safely relocate an agent, report the concrete native dependency in [references/native-relocation.md](references/native-relocation.md) and stop before the claim. Do not archive workers merely to try importing them elsewhere.
5. **Claim the role.** Immediately before, refresh self, the bound outgoing PM, and every same-project `role=pm` record globally. Require self unarchived, the bound PM unarchived and still carrying `role=pm/project=<name>`, and no eligible PM newer than self other than an owner-named bound PM; anything else stops before mutation. Then set self's `role=pm` and `project` labels and clear the bound PM's `role`, preserving every other label on both. In Paseo 0.10.2 and 0.11.1, `paseo agent update <id> --label 'role='` clears PM membership with an empty string (labels merge as a patch); the public update schema does not accept null deletion. No compare-and-set exists, so the direction rule, not the label write, is what keeps two takeovers from both proceeding. Re-read both: self must carry `role=pm/project=<name>`, and the bound PM's `role` must not equal `pm`. Any other result means another takeover is acting: stop, report the observed labels, and change nothing more, including the other agent's labels. With no bound PM, the claim only sets self's labels. From a verified claim on, self is the project memory pair's sole writer.
6. **Transfer and verify.** Rename self's workspace to the basename of its directory. Move retained agents to self's workspace with the operation checked in step 4 and transfer their ownership through the supported parent operation; preserve unrelated labels. Set self's name to `<Project> PM` and its exact catalog model ID, preserving its other settings. Inspect self and every retained agent: verify destination workspace, parent ownership, unchanged Paseo/native IDs and history, catalog model, settings, roles, usable cwd, and unarchived state. On a failed check, stop before label cleanup or archiving and report any partial changes within the resolved project; self keeps the role, and the bound PM stays unarchived without it.
7. **Retire stale labels.** Re-query globally and retire only stale `role=pm` assignments on other confirmed same-project candidates older than self, beyond self and the bound PM, with the same supported label update. Verify that `role` no longer equals `pm`. Preserve their other labels, sessions, history, settings, lifecycle state, and workspaces. Announce the affected IDs and verify each label change and preservation. A candidate newer than self that appeared since the claim, or any unconfirmed candidate, is left untouched and reported; it blocks the archive. A failed cleanup blocks the final archive. Duplicate labels alone do not require an owner selection question or authorize archiving those other agents.
8. **Archive last.** Immediately before, refresh globally: self must be unarchived and the only unarchived `role=pm/project=<name>` match, and the bound PM's `role` must still not equal `pm`. Otherwise stop without archiving. Then archive only the bound old PM. Re-query globally: exactly one unarchived `role=pm/project=<name>` match must be self, and retained agents must remain unarchived in self's workspace. Archive the old workspace only when the owner explicitly requested it: re-inventory every remaining agent and terminal, verify retained agents are absent, and confirm the cascade is within that request. Never archive the replacement workspace. Local checkout files and native history must survive; stop if removing a managed worktree would violate that requirement.

Update the owned root memory under its local commit/ignore policy. Report the new PM ID/model, bound old PM ID and evidence, the claim's label changes, archived PM ID, stale PM label removals, retained-agent placement, any workspace archive, and unresolved dependencies. Then continue the assigned work.

## Installed provenance limits

Observed in Paseo 0.10.2: protocol `messages.js` defines `agent.fork_context.request` with `agentId`, optional `boundaryCursor`/`boundaryMessageId`, and `requestId`. The response contains the requested `agentId`, attachment, item count, boundary, and error; client `daemon-client.js` method `buildAgentForkContext` retrieves that source history. This generates context for the requested agent, not a child-to-source lookup. Server `agent/activity-curator.js` generates an attachment whose `Source agent:` is a title and `Source directory:` is a cwd, not a full PM ID. Protocol `AgentSnapshotPayloadSchema` has no persisted fork-source field, and the CLI has no fork-context command. Use provenance actually available in the current fork or supplied context and corroborate it; otherwise use creation-time selection. Recheck the installed protocol/client and CLI surface when versions change rather than inventing metadata fields.

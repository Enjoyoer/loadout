# Worker routing

## Resolve

An owner-named model, effort, or Fast wins and is never adjusted. An owner-named model or a burn route holds only for that task or burn. When it ends, launch new workers on the OPC default route. Pi has Fast on GPT routes: `--owner-fast on` records it, and the Worker builder sets the `opc.service-tier` label that the composer's Fast pill shows. On Pi, Fast is the agent label `opc.service-tier=fast`, not a catalog model or thinking level, so the model catalog never lists it; outside the builder set it with `labels:{"opc.service-tier":"fast"}` on `create_agent` or `update_agent`, or on the CLI with `paseo run --label opc.service-tier=fast` or `paseo agent update <id> --label opc.service-tier=fast`, and read it back with `get_agent_status`. A Pi GPT route with no label runs Standard (no label means Fast off), except Luna: the Pi router sends Fast on every Luna turn whatever the label says (owner 2026-11-17); the builder still writes an explicit `opc.service-tier=standard` for a Fast-off GPT route. Verify the label (`get_agent_status` or the Fast pill) before reporting a route. Never skip the builder with a raw `create_agent` for a Worker. Otherwise pick the task class below and resolve it with `resolveWorkerRoute` from `scripts/route.mjs`, or from a shell:

`node scripts/route.mjs --class <class|main-pm|opn-browser> [--scope ordinary|preserved] [--task TASK_JSON --lane SLUG]`

It prints one human summary line to `stderr` and one JSON object to `stdout`: `{route, reason, provider, model, effort, fast, host, nextFallback, proofRequired}` (plus `fallbackChain` for `main-pm`). `--scope` applies only to `code` and its aliases (`scope` in `resolveWorkerRoute`): `ordinary`, the default, is fresh ordinary OPC code; `preserved` is a UI build or OPN work, named by the caller and never inferred from an alias or label (see [Code scope](#code-scope "runtime")). Bare `--class` applies the fresh trusted forcing switch, live Mac skip holds, and read-only parity peek without creating files or consuming turns; it separates policy selection (`proofRequired: true`) from exact target/workspace proof. Every fresh class-default or UI-class launch, brief, and record (`recordWorkerRoute`, `buildManagedWorkerRequest`, `buildInPlaceWorkerRequest`, `buildDelegatedBrief`, bound or unbound) requires a live route from `resolveWorkerRoute` in the same process, at most 60 seconds old, resolved for that exact task and lane (pass `task` and `lane` to `resolveWorkerRoute`), and only while the live Mac policy it read (switch, `devin-ready.json`, `agy-quota.json`, model holds, local daemon) is unchanged; pasted, cloned, remembered, other-lane, and stale routes are refused, an owner-named route is the owner's own, and missing/stale proof for an admitted agy selection fails closed without inventing Sol or silently substituting Opus. Add `--owner-model ID --owner-effort LEVEL [--owner-fast on|off]` for an owner-named route and `--catalog FILE` for saved Pi catalog rows (default: `paseo provider models pi --json`). With `--task` and `--lane` it records `{route, reason}` in the task's `routes` and returns an already recorded lane unchanged, so repairs and resumes keep their route; for a recorded lane it refuses `--class`, `--owner-model`, `--owner-effort`, or `--owner-fast` that would select another route, so resume it with no route flags or with the ones that selected it (`--scope preserved` never replays an ordinary Astra lane). Pass `route` unchanged to `buildManagedWorkerRequest` and `reason` to `buildDelegatedBrief`. Give both builders the destination task as `task: readTask(taskPath)`, the lane (`buildDelegatedBrief` takes `lane` too; `buildManagedWorkerRequest` refuses a `taskId` other than the record's id), and the lane's class as `taskClass` (a UI task's lanes are `ui-design`, the default, or `ui-check`); pass the same `taskClass` when recording, and the Pi catalog rows as `catalog` to `buildDelegatedBrief` and `recordWorkerRoute` where you have them. Omit `provider` and `agentSettings` when calling the builders, or pass only the exact provider and settings the validated route maps to. Every route, recorded or fresh, keeps the owner's hard rules for its lane's class: `code` and its aliases never run a GPT or web model except the ordinary Astra default below, `ui-design` and `ui-check` are exactly Fable high, Fast off (without a catalog the model id must name Fable; otherwise ask the owner to use the class instead), Fable runs only at high with Fast off in every lane, `smoke`, `sites` and a `watcher` route on Luna never run Fast off (an owner-named route for them needs `--owner-fast on`), and no route runs below its class minimum. Inside them an owner-named route keeps its model and effort. The only GPT exceptions the resolver admits for `code` are the ordinary task default, exactly Pi `fleet/gpt-6.2-astra` medium, Fast off (decision 411a; an owner-named GPT route for `code` is still refused), and the recorded Sol medium `pace-backup` on a forced [Antigravity replacement](#antigravity-replacement "runtime") lane or a [code parity](#code-parity "runtime") agy turn (outside the resolver, an OPN `code` worker has the named Sol high fallback in [PMs](#pms)). Replaying a recorded route does not by itself authorize a rebuild: if a recorded lane no longer fits its class minimum, ceiling, catalog, or hard rules, stop and resolve a new lane instead (supported legacy routes that still rebuild are pre-411a `code` on Opus up to `xhigh`, pre-411a `review` on Sol `high` with its recorded Fast, pre-411a `review-security` on Sol `xhigh` Fast on, pre-Sol `watcher` on Luna `xhigh` Fast on, pre-332 `review-security` Opus/non-GPT `high`+ Fast off, pre-split `plan` on Sol `high` Fast off, and GPT defaults with their recorded Fast). Kinds outside the table go to the owner.

Default review uses `review` (its route under [Review route](#review-route "runtime")) as a read-only Pi lane on the exact PR head, with [Simplifier remit](simplifier-review.md "runtime") as its brief. Fast means Pi's Fast toggle on Pi GPT routes; native Codex browser lanes set `settings.features.fast_mode` from the route (true by default since decision 327) and an explicit unattended `settings.modeId`.

### Code scope

Decision 411a. A fresh `code` lane (aliases included) with no scope, or `--scope ordinary`, is ordinary OPC code and takes Pi `fleet/gpt-6.2-astra` medium, Fast off (`opc.service-tier=standard`). Two uses keep the shared Opus high, Fast off row, and their caller names `--scope preserved` (`scope: 'preserved'`) every time: the build lane of [UI work](#ui-work "runtime") and an OPN worker on the `code` class. Nothing infers the scope from an alias, a label, or the task. Scope changes only the plain class default: Devin-first, the forced ladder, and [code parity](#code-parity "runtime"), including its Opus turn on Opus high, take precedence unchanged in either scope, and recorded lanes keep their routes.

### Review route

Decision 411a. Before starting a `review` or `review-security` lane, the PM reads the task's recorded code lanes (`routes`). If any recorded code lane ran an Anthropic model (Opus or Fable, on Pi, `devin-first`, agy Opus High, or Cursor Claude), the PM names the existing Sol route:

`node scripts/route.mjs --class review --owner-model fleet/gpt-6.2-sol --owner-effort high --owner-fast on --task T --lane L`

`node scripts/route.mjs --class review-security --owner-model fleet/gpt-6.2-sol --owner-effort xhigh --owner-fast on --task T --lane L`

Otherwise, including Astra, Neon, Sol or Cursor Neon code, work with no task record or no recorded code lane, and OPN work, it uses the class default (Opus high, or Opus xhigh for `review-security`, Fast off). This is a PM rule: the resolver records no author and checks none, and it is not a quota fallback.

### Research

A `research` lane is read-only like `plan`: `buildDelegatedBrief` prefixes the read-only line and tells the Worker to return findings with sources and to ask Fable through `$ask-fable` (`python3 ~/.local/bin/fable-ask <question-file>`) for a judgment call, so Fable answers one question, starts no Fable agent, and never runs the lane. Pre-split research lanes recorded before the split carry `kind: plan` and must replay and rebuild with no route flags or `--class plan` (and `taskClass: 'plan'`), never `--class research`.

### Security review escalation

Only one security reviewer runs at a time, never two in parallel.

This escalation applies only when the primary security review ran on the Sol route under [Review route](#review-route "runtime"). A primary Opus review that fails or returns a blocker follows [review rule R1](web-reviewer.md#review-rules "branch:review"), with no Sol or other escalation.

PM trigger: the Sol lane has ended in a terminal failure (a launch failure, a provider refusal, a rate limit or quota stop, or a failure that a continue follow-up under [Errors](#errors "runtime") did not clear), or it has returned a blocker verdict. Only then, after the Sol lane is terminal, may the PM start one separate read-only lane on Opus xhigh, Fast off, on the same exact head, with the same correctness brief, as a new lane named `security-escalation` (a later candidate in the same task takes `security-escalation-2`, then `-3`; lane slugs stay at most 40 characters) through the explicit escalation command:

`node scripts/route.mjs --class review-security --owner-model fleet/claude-opus-5-5 --owner-effort xhigh --owner-fast off --task T --lane security-escalation`

Decision 332 already authorizes this escalation after a terminal Sol failure or a Sol blocker verdict, so the PM runs it without asking the owner again; it records as an owner-named route, and nothing starts it on its own. A failed review, Sol or Opus, is never approval. The escalation lane does not clear a Sol blocker: every blocker stays open until it is fixed and passes the fix check under [review rule R1](web-reviewer.md#review-rules "branch:review"). If the Opus lane also fails, stop and report NOT APPROVED to the owner.

### OPN browser workers

Named `browser` exception (owner 2026-11-17, a recorded task-type exception, so the owner does not have to name the model): a fresh PM-started OPN browser worker, started in the PM's own workspace so it shares the Paseo browser and its signed-in tabs, resolves deterministically through `node scripts/route.mjs --class opn-browser` to native Codex `codex/gpt-6.2-sol`, thinking low, Fast on (owner decision 412a, 2026-11-27; replaces the Pi route of decision 327). Native Codex gets the Paseo MCP browser tools from its runtime Paseo MCP server. The resolver reads the native Codex catalog (`paseo provider models codex --json`; `--catalog FILE` and `resolveWorkerRoute`'s `catalog` hold those rows), and a Pi row such as `fleet/gpt-6.2-sol` never authorizes the lane. Pass the native Codex `inspect_provider` result, with its `list_models` rows as `models`, as `capabilities` to `buildInPlaceWorkerRequest` with `taskClass: 'opn-browser'`; both must serve exactly one unprefixed `gpt-6.2-sol` at low thinking, and the request runs the native Codex `full-access` mode, which must be advertised exactly once (stock Paseo may leave it unflagged) with no other unattended mode. No caller override changes it (omit `--owner-*`, `ownerRoute`, `surface`, `nativeAuthorization`, remote target, and workspace/placement overrides), and it is never recorded as a lane.

## Web reviewer

The `reviewer` fixed role is separate: it is the one ChatGPT web lane (Web Pro) only for browser review explicitly enabled by the owner, not a Worker class, and the class table does not change it.

## PMs

This file is the one model map for OPC and OPN. The three main PMs and the fresh PM that `unstuck` starts run on Opus high (Pi `fleet/claude-opus-5-5`, thinking high, Fast off; owner 2026-11-18); every other project PM and every child PM runs on Opus medium (Pi `fleet/claude-opus-5-5`, thinking medium, Fast off; decision 405a), unless the owner names another model for it. `node scripts/route.mjs --class main-pm` exposes the read-only `main-pm` policy ladder for the three main PMs (Config, Work, Personal): default Claude Opus high even off pace, then only Neon High or Opus High (owner 404b correction, 2026-11-25): native `agy-opc/gemini-4-neon-high` -> Cursor `cursor/gemini-4-neon` -> `agy-opc/claude-opus-5-5-high`, applying live Mac skip holds and Config's `agy-quota.json` projection to the agy steps without touching triggers, sessions, or CPA. Sol is never a main-PM fallback. Exactly two named starts fall back to Sol high (`pi/fleet/gpt-6.2-sol`, thinking high), only when Opus high is missing from the catalog, fails to start, or returns a quota error: the fresh PM that `unstuck` starts, and an OPN worker on the `code` class (scope `preserved`). It is never a fallback from Astra. OPC `code` lanes never take that fallback: they stop and report to their PM. A PM's own model never passes to its lanes or workers; each takes its live resolved class route.

## Fable

Fable runs on the OPC `plan`, `ui-design` and `ui-check` lanes, or wherever the owner names it. At most 5 Fable agents run at once across the fleet, PMs and `plan` lanes included; before starting one, count the running Fable agents on every host.

## UI work

Fable designs and checks; Opus builds. In UI work, Fable is only for real visual design: a new screen, a layout change, or a new component. Copy, labels, states, error text, renames, and guards with no layout change are `code` only, with no Fable lane.

1. `ui-design` (Fable high, Fast off, read-only) takes the current screens, as screenshots and code, and returns a short design spec plus a static mockup (HTML/CSS or images) at a scratch path the PM names. It makes no repository edits and opens no PR. At most one per task; a second needs the owner's OK.
2. A normal `code` lane on scope `preserved` (Opus high, Fast off; never the ordinary Astra default) builds: it implements the spec and mockup exactly, plus the logic, and opens the PR with [before and after screenshots](pr-evidence.md "branch:evidence").
3. `ui-check` (Fable high, Fast off, read-only) is optional and runs one pass: it compares the after-screenshots to the mockup and returns a fix list. The code lane applies the fixes.

The `ui-design` and `ui-check` lanes run in a UI task (the Fable `plan` lane does not), created with `createTask({..., ui: true})`; pass `ui: true` to `selectTopology`. Its lanes take only `ui-design` (the default when no `taskClass` is given) or `ui-check`, and the build runs in a separate normal `code` task. UI tasks forbid all scouts and browser review, and UI work never uses a GPT or web model (no Sol, Terra, Luna, or Astra Worker, no scouts of any model, and no web reviewer). Outside Fable high, Fast off, a UI lane takes only the approved positive-signal exceptions under [Antigravity replacement](#antigravity-replacement "runtime") (Devin-first Pi Opus high, or the agy ladder on positive fresh `fableUnavailable` evidence, never Cursor or pace alone).

## Cursor overflow

Owner rule (2026-11-21). Cursor's small monthly Other Models pool is overflow only, so it is never spent on work native Antigravity covers.

Cursor runs only on the configured Cursor host entry: in the private `~/.config/opc/neon-remote-targets.json`, the one target entry that adds `"cursorOverflow": true` to its `endpoint`, `platform` and `state`. That entry must also be `armed` with platform `linux`. No such entry, more than one, or one that is not armed linux means no Cursor host, and every Cursor lane fails closed. Host names live only in that file.

- The default overflow model is provider `cursor` with model `gemini-4-neon`. Use it only when native Antigravity is capped or unavailable.
- Use `cursor` with `claude-opus-5-5` only for a task that strictly requires Claude (a `code` or review Worker that must stay on Claude) while the Claude pool is at its cap.
- Always pass `--model` explicitly and keep the defaults: 300k context, Fast off, no 1M or Max mode. Never fall back to `Auto` for Claude-only work.
- For automated `gemini-4-neon` overflow, the resolver checks the Cursor host's `paseo usage` quota preflight automatically; before starting a manual `claude-opus-5-5` overflow lane, check that the Other Models pool has room on `cursor.com/dashboard/spending`, and if it is spent, wait for the Claude or Antigravity reset instead.
- Give each Cursor Worker one bounded task, label it `lane=cursor-overflow`, and archive it when done. Afterwards, restore the `~/.cursor/cli-config.json` model to `default` if it changed.
- If a create fails in under 2 seconds with `Authentication required`, refresh the `cursor` provider snapshot and retry once. Never run `cursor-agent login`.
- As Worker overflow, never use Cursor for a PM's own model (a main PM's only Cursor step is its [`main-pm` chain](#pms)), for Fable (no zero data retention), for a main lane, or for a payment-data project.
- Never turn on on-demand spending, and never accept a plan switch or a unify offer. A reply saying "Upgrade your plan to continue" means stop; do not retry.

## Settings

OPC routing reads one optional key of `~/.config/opc/routing.json`, `antigravityFallback`, and only for the off-pace and [code parity](#code-parity "runtime") routes below; its `pq` key and every other key belong to other readers and are never read or rewritten.

### Antigravity replacement

Settled precedence (owner decisions 314a, 390a, 393a, 397c, 398a, 399a):
1. **Devin-first Pi Opus High (397c/399a)**: for fresh `code`, `plan`, `ui-design` (`ui`), and `ui-check` lanes, read ONLY Mac owner-owned regular `~/.config/opc/devin-ready.json` (`0644`). When ready, select Pi `fleet/claude-opus-5-5`, thinking high, Fast off (`source: 'devin-first'`; read-only preserved for `plan`/UI).
2. **Off-pace `code` ladder (393a/398a/399a)**: when Devin is not ready and trusted `antigravityFallback` is forced on (both booleans true), a new default `code` lane (aliases included) runs in strict order:
   - **`agy-opc/gemini-4-neon-high` (Neon High)** first (`high`, Fast off, mode `auto`, `auto_accept: true`).
   - **`agy-opc/claude-opus-5-5-high` (agy Opus High)** ONLY when Neon High is held or positively unavailable.
   - **Cursor Neon overflow (`cursor/gemini-4-neon`, decision 398a)**: ONLY after both Neon High and agy Opus High are held or positively unavailable, and ONLY on the configured Cursor host entry ([Cursor overflow](#cursor-overflow "runtime")). The lane must be an eligible bounded `code` lane: `task.payment_data === false` (`createTask({paymentData: false})`), a non-`main` lane, a valid private `cursorExcludedProjects` list in `routing.json`, and authenticated project ancestry (matching live git origin and readable launcher chain); exclusions match slug, origin, checkout path, and launcher working directories, and unreadable or mismatched ancestry is ineligible (never route around it). The launch takes `readRemoteAgyTarget({serverId, workspace, cursorLaunch: true})`, runs explicit `cursor/gemini-4-neon` on its one unattended mode with model defaults (300k, Fast off, no Max or Auto), and is labelled `lane=cursor-overflow`.
   - **Pi `fleet/gpt-6.2-sol` medium, Fast off (`source: 'pace-backup'`, `opc.service-tier=standard`)** ONLY when both Neon High and agy Opus High are held or positively unavailable AND Cursor is ineligible or positively unavailable.
   - Missing or stale proof for the selected agy or Cursor step fails closed: never infer cap from missing proof, never invent Sol, and never silently substitute Opus.
3. **Decision 390a (`plan`, `ui-design`, `ui-check`)**: fresh `plan`, `ui-design` (`ui`), and `ui-check` lanes stay Fable High, Fast off regardless of pace, entering the agy ladder (never Cursor) ONLY with positive fresh `fableUnavailable` evidence (`provider: 'pi'`, Fable model, same target, within 1 hour, `not-serving`/`quota-exhausted`/`unavailable`), never from missing/unknown signals or pace alone.

Nothing else moves: PMs (main and child), owner-named routes (`ownerRoute`), reviews (`review`, `review-security` and its decision 332 escalation), `research` (Terra), `watcher` (Sol), `smoke` (Luna), `sites`, `browser`/`browser-hard`, `opn-browser`, lanes with a recorded route, running agents, held or unproved remote hosts, ULR project PM swaps, and excluded launchers (`replacementExcludedLaunchers`).

The switch is `antigravityFallback: {enabled, state: {off_pace, as_of, expires_at}}`, written only by Config's pace job (mode `0600`) and read strictly on macOS as an owner-owned, non-symlink, no-group/world-write, fresh safe file (`as_of <= now < expires_at`). Both true = forced (`code` ladder); both false = not forced ([code parity](#code-parity "runtime"), `code` only); absent, stale, unknown, unsafe, or contradictory stays on the class default. Never copy switch values, `retry_at`, raw error text, quota/reset figures, payment-project identifiers, or account labels into reasons, briefs, records, logs, remote hosts, or repo, and never access credentials or CPA.

Per-model holds and bounded opposite-model probes (`scripts/agy-holds.mjs`): the error backstop runs from the launch workflow (OPC and OPN managed lanes alike): register every replacement launch with `validateManagedWorkerLaunch(prepared, created, taskPath)` so `record-terminal` can bind it, and when a launched `agy-opc` replacement Worker of a recorded lane finishes in error, run `node scripts/agy-holds.mjs record-terminal --task TASK_JSON --lane SLUG --agent AGENT_ID` before reporting or relaunching. Opposite-model probes (`beginOppositeModelProbe` / `settleOppositeModelProbe`) are one-shot per direction per target only while an active source hold exists, with no retries.

Invocation: pass `replacement: {task, lane, target, proof?, unavailable?, remote?, fableUnavailable?}` to `resolveWorkerRoute` and `recordWorkerRoute` (any other key, including a caller `cursor` preflight, admits nothing; there is no caller Devin override, the resolver always reads `devin-ready.json`); `proof` and local `unavailable` accept a single entry or a 1–2 item array for per-model evidence (`model: 'gemini-4-neon-high' | 'claude-opus-5-5-high'` with `finding: 'not-serving'`). A local `agy-opc` launch passes the `inspect_provider` draft as `capabilities` with `checked_at` (RFC 3339 UTC, when it was read for this launch, at most 2 minutes old). Remote targets use `readRemoteAgyTarget` (`readRemoteNeonTarget` alias) over the authenticated stock `@getpaseo/cli@0.15.3` SDK: a resolve read (no `workspace`) for admission, and a launch read of the managed workspace with `model`, `allowBackup: true` (remote Pi Sol medium backup) or `cursorLaunch: true` (Cursor, configured Cursor host only), refusing caller `unavailable` and caller `capabilities`. A launch-only, Pi-only, or Cursor-only read, a not-ready status, or a partial model/mode subset never establishes remote agy unavailability and never unlocks Cursor or Sol.

### Code parity

## Errors

Network and proxy errors, such as `Connection error` or a 502 `backend unavailable`, are retried on the same route by sending the same Worker a continue follow-up. They never change the model or effort. Rate limits, unavailable capabilities, and real launch failures still stop the lane; substitution requires a new explicit owner decision.

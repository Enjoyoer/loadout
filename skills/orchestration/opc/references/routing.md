# Worker routing

## Resolve

An owner-named model, effort, or Fast wins and is never adjusted. An owner-named model or a burn route holds only for that task or burn. When it ends, launch new workers on the OPC default route. Pi has Fast on GPT routes: `--owner-fast on` records it, and the Worker builder sets the `opc.service-tier` label that the composer's Fast pill shows. On Pi, Fast is the agent label `opc.service-tier=fast`, not a catalog model or thinking level, so the model catalog never lists it; outside the builder set it with `labels:{"opc.service-tier":"fast"}` on `create_agent` or `update_agent`, or on the CLI with `paseo run --label opc.service-tier=fast` or `paseo agent update <id> --label opc.service-tier=fast`, and read it back with `get_agent_status`. A Pi GPT route with no label runs Standard (Fast is off by default fleet-wide), except Luna: the Pi router sends Fast on every Luna turn whatever the label says (owner 2026-11-17); the builder still writes an explicit `opc.service-tier=standard` for a Fast-off GPT route. pi-fast-toggle applies the same label. Verify the label (`get_agent_status` or the Fast pill) before reporting a route. Never report Fast as unavailable on Pi, and never skip the builder with a raw `create_agent` for a Worker. Otherwise pick the task class below and resolve it with `resolveWorkerRoute` from `scripts/route.mjs`, or from a shell:

`node scripts/route.mjs --class <class> [--task TASK_JSON --lane SLUG]`

It prints one JSON object, `{route, reason}` (also `provider` for browser defaults). Add `--owner-model ID --owner-effort LEVEL [--owner-fast on|off]` for an owner-named route and `--catalog FILE` for saved Pi catalog rows (default: `paseo provider models pi --json`). With `--task` and `--lane` it records `{route, reason}` in the task's `routes` and returns an already recorded lane unchanged, so repairs and resumes keep their route; for a recorded lane it refuses `--class`, `--owner-model`, `--owner-effort`, or `--owner-fast` that would select another route, so resume it with no route flags or with the ones that selected it. A new route is checked against the class table once, when it is recorded; later reads check only its shape, so a later class change never strands a task. Pass `route` unchanged to `buildManagedWorkerRequest` and `reason` to `buildDelegatedBrief`. Give both builders the destination task as `task: readTask(taskPath)`, the lane (`buildDelegatedBrief` takes `lane` too; `buildManagedWorkerRequest` refuses a `taskId` other than the record's id), and the lane's class as `taskClass` (a UI task's lanes are `ui-design`, the default, or `ui-check`); pass the same `taskClass` when recording, and the Pi catalog rows as `catalog` to `buildDelegatedBrief` and `recordWorkerRoute` where you have them. With a task, an explicit `provider` is checked after the route and must be exactly the provider the validated route maps to, with its settings. Task records are bookkeeping, not routing authority: the source a route records grants nothing. Every route, recorded or fresh, keeps the owner's hard rules for its lane's class: `code` and its aliases never run a GPT or web model, `ui-design` and `ui-check` are exactly Fable high, Fast off (without a catalog the model id must name Fable), Fable never runs at another level in any lane, `smoke`, `sites` and a `watcher` route on Luna never run Fast off, and no route runs below its class minimum. Inside them an owner-named route keeps its model and effort. A task default runs its class's own model: with a catalog exactly the class's row, without one a model id that names the class's label. A lane with a recorded route takes only that route, on the request, brief, and recording paths. It rebuilds (repair, restart) as long as it still fits; a task default must also be the class's catalog label with the class's Fast (a GPT class lane recorded with Fast on before Fast went off by default keeps it), at any effort from the class minimum up to its ceiling (code and `review-security` high..xhigh, so an earlier Opus xhigh lane rebuilds; a recorded Opus medium lane is below the minimum and stops, so start a new lane), which the Pi catalog must still serve. A `watcher` lane recorded as the former default Luna xhigh, Fast on, before watchers moved to Sol, still rebuilds on that route; a new `watcher` task default takes Sol low. A fresh lane's route is checked as new against today's table and its class. Kinds outside the table go to the owner.

## Classes

Labels resolve through the target Pi catalog; browser classes launch with native Codex catalog IDs (`gpt-6.2-sol`). Routes are the minimum (owner rule): nothing lowers a route. Each class runs at its default; only an owner-named route changes it.

|---|---|---|---|
| `code` | implementation, bounded edits, CI fixes, automation code, mechanical edits | Opus high (owner 2026-11-18) | off |
| `ui-design` | read-only, at most one per task: design spec and static mockup for a new screen, layout change, or new component | Fable high, owner rule | off |
| `ui-check` | read-only, optional, one pass: compare after-screenshots to the mockup, return a fix list | Fable high, owner rule | off |

| `browser` | website navigation, data entry, repetitive and high-volume browser automation, computer use, native computer-use Workers, desktop application workflows (owner 2026-11-18) | native Codex Sol low (owner 2026-11-17); an OPN browser worker takes the [named exception](#opn-browser-workers "runtime") | off |

Owner 2026-10-14 grants standing native Codex authorization to `browser` and `browser-hard`, and owner 2026-11-17 to `sites`, without per-task `nativeAuthorization`; other classes stay on Pi unless explicitly authorized per task, except a recorded [Antigravity replacement](#antigravity-replacement "runtime") lane, whose switch and admission stand in for it.

Browser Worker briefs must say: "Use the Paseo MCP server's browser_* tools (discover them if deferred), not cua_repl or native Chrome computer control. Before pressing Enter or clicking Send or Submit in any web form or chat composer, take a fresh browser_snapshot and check the field holds exactly the text you typed; if it holds anything else, clear it, report it, and do not send. Prefer clicking the Send button over pressing Enter." Reason: the Paseo browser tab lives inside the owner's desktop app, and an agent's click can move keyboard focus into the page, so the owner's typing lands in the field.

The PM picks `browser-hard` and records why only for browser work that is fragile, ambiguous or failing repeatedly on `browser`. Computer use and desktop application workflows stay on `browser`.

Aliases: `code-bounded`, `test-fix`, `automation`, `mechanical` resolve to `code`; `research` to `plan`; `review-critical`, `review-general` to `review`; `security` to `review-security`; `ui` (compatibility) to `ui-design`, with new routes and reasons naming the canonical class.

Local code lanes default to Opus high, and `plan`, `ui-design` and `ui-check` run Fable high everywhere. Code, `review-security` and their aliases never run on a GPT model, and an owner-named GPT or web route for them is refused; the one exception is the recorded [off-pace backup](#antigravity-replacement "runtime") of a `code` lane. Planning and investigation use the read-only `plan` Worker class on Fable high, Fast off (owner 2026-11-18); Opus implements the returned plan. A `plan` lane recorded as the former default Sol high, Fast off, still rebuilds on that route. The `scout` fixed role uses its row above. During its trial, each task that runs a scout records one line, `scout_trial`, in its task record (see [Task binding](imp-execution.md#task-binding "runtime")), and the trial is judged from those lines on 2026-11-26. Every class and fixed role runs Fast off by default (owner 2026-11-07: Fast costs far more than the time it saves), except the Luna classes `smoke` and `sites`, which run Fast on (owner 2026-11-17: Fast must be on for all Luna calls). `watcher` runs Sol low, Fast off (owner 2026-11-18), but a `watcher` route on Luna still runs Fast on. A `smoke` or `sites` route, or a `watcher` route on Luna, with Fast off is refused, so an owner-named route for them needs `--owner-fast on`; the Pi router sends Fast on every Luna turn in any lane. Sol, Astra and Fable stay Fast off. Fable always runs at high with Fast off; Fast on Sol or Astra is an owner-named exception for one task, such as the owner's 3D work on Astra: record it with `--owner-fast on`. PMs stay on Opus and delegate all browser, computer-use and scouting work to these GPT lanes and research to the `plan` lane, never doing it themselves; UI design goes to `ui-design` under the UI rule below. Default review uses `review` as a read-only Pi lane on the exact PR head, with [Simplifier remit](simplifier-review.md "runtime") as its brief. Pick `review-security` instead for a diff touching auth, secrets or credentials, permissions or sandboxing, firewall or network exposure, backups, or deletion and archive paths (owner rule: GPT trips the provider's cyber-safety filter on that work); its brief asks for a correctness review, and the builder prefixes that wording. Fast means Pi's Fast toggle on Pi GPT routes; native Codex browser lanes set `settings.features.fast_mode` from the route (false unless the owner named Fast) and an explicit unattended `settings.modeId`. A lane recorded with Fast on before this default changed keeps Fast on through repairs and resumes.

### OPN browser workers

Named `browser` exception (owner 2026-11-17, a recorded task-type exception, so the owner does not have to name the model): an OPN browser worker, started in the PM's own workspace so it shares the Paseo browser and its signed-in tabs, runs on Pi `fleet/gpt-6.2-sol`, thinking low, Fast off, not on the native Codex `browser` route. `route.mjs` does not resolve this exception; start the worker on exactly this route.

## Web reviewer

The `reviewer` fixed role is separate: it is the one ChatGPT web lane (Web Pro) only for browser review explicitly enabled by the owner, not a Worker class, and the class table does not change it.

## PMs

This file is the one model map for OPC and OPN. Every PM, main and child, runs on Opus high (Pi `fleet/claude-opus-5-5`, thinking high; owner 2026-11-18), unless the owner names another model for it, and has no fallback. Exactly two named starts fall back when Opus high is unavailable: the fresh PM that `unstuck` starts, and an OPN worker on the `code` class. Each then starts on Sol high (Pi `fleet/gpt-6.2-sol`, thinking high). Opus high counts as unavailable only when it is missing from the catalog, or the agent fails to start or returns a quota error. Every other PM stays on Opus high; OPC `code` lanes and every `review-security` lane never take that fallback: they stop and report to their PM. A PM's own model never passes to its lanes or workers; each takes its class route.

## Fable

Fable runs on the OPC `plan`, `ui-design` and `ui-check` lanes, or wherever the owner names it. Implementers and reviewers use Opus or Sol, and no lane inherits Fable from its PM. At most 5 Fable agents run at once across the fleet, PMs and `plan` lanes included; before starting one, count the running Fable agents on every host. When the owner names Fable for a code lane, `buildDelegatedBrief` starts its brief with an ownership line (the owner and long-term maintainer of the codebase, its design up to it within the brief's permitted changes), per Anthropic's Fable 5.2 prompting guidance.

## UI work

Fable designs and checks; Opus builds. In UI work, Fable is only for real visual design: a new screen, a layout change, or a new component. Copy, labels, states, error text, renames, and guards with no layout change are `code` only, with no Fable lane.

1. `ui-design` (Fable high, Fast off, read-only) takes the current screens, as screenshots and code, and returns a short design spec plus a static mockup (HTML/CSS or images) at a scratch path the PM names. It makes no repository edits and opens no PR. At most one per task; a second needs the owner's OK.
2. A normal `code` lane (Opus high) builds: it implements the spec and mockup exactly, plus the logic, and opens the PR with [before and after screenshots](pr-evidence.md "branch:evidence").
3. `ui-check` (Fable high, Fast off, read-only) is optional and runs one pass: it compares the after-screenshots to the mockup and returns a fix list. The code lane applies the fixes.

The `ui-design` and `ui-check` lanes run in a UI task (the Fable `plan` lane does not), created with `createTask({..., ui: true})`; pass `ui: true` to `selectTopology`. Its lanes take only `ui-design` (the default when no `taskClass` is given) or `ui-check`, and the build runs in a separate normal `code` task. Both classes resolve to owner-explicit routes with reasons `ui-design: owner rule, Fable high, no GPT, read-only` `ui-check: owner rule, Fable high, no GPT, read-only`; `buildDelegatedBrief` marks them read-only. UI work never uses a GPT or web model: no Sol, Luna, or Astra Worker, no Sol scouts, and no web reviewer in `ui-design` or `ui-check`. The UI task refuses browser review, `recordWorkerRoute` and the Worker builders given the task refuse any other class and anything but Fable high, Fast off, with a Fable model id, and the topology runs no scouts. An owner-named route still wins inside these rules; one for `ui-design` or `ui-check` other than Fable high, Fast off is refused, so ask the owner to use the class instead. The old `ui` class name is an alias of `ui-design`.

## Cursor overflow

Owner rule (2026-11-21). Cursor's small monthly Other Models pool is overflow only, so it is never spent on work native Antigravity covers.

- The default overflow model is provider `cursor` with model `gemini-4-neon`. Use it only when native Antigravity is capped or unavailable.
- Use `cursor` with `claude-opus-5-5` only for a task that strictly requires Claude (a `code` or review Worker that must stay on Claude) while the Claude pool is at its cap.
- Always pass `--model` explicitly and keep the defaults: 300k context, Fast off, no 1M or Max mode. Never fall back to `Auto` for Claude-only work.
- Before starting either, check that the Other Models pool has room on `cursor.com/dashboard/spending`. If it is spent, wait for the Claude or Antigravity reset instead.
- Give each Cursor Worker one bounded task, label it `lane=cursor-overflow`, and archive it when done. Afterwards, restore the `~/.cursor/cli-config.json` model to `default` if it changed.
- If a create fails in under 2 seconds with `Authentication required`, refresh the `cursor` provider snapshot and retry once. Never run `cursor-agent login`.
- Never use Cursor for a PM, for Fable (no zero data retention), for a main lane, or for a payment-data project.
- Never turn on on-demand spending, and never accept a plan switch or a unify offer. A reply saying "Upgrade your plan to continue" means stop; do not retry.

## Settings

OPC routing reads one optional key of `~/.config/opc/routing.json`, `antigravityFallback`, and only for the off-pace routes below; its `pq` key and every other key belong to other readers and are never read or rewritten.

### Antigravity replacement

Owner decision 314a (2026-11-21): while Claude is off pace, a new `code` Worker lane on the Opus high, Fast off default runs instead on the generic ACP provider `agy-opc`, model `gemini-4-neon-high`, thinking high, Fast off, in agy's native mode `auto` with the generic ACP feature `auto_accept` true (Paseo approves its ACP permission prompts). `default`, `accept-edits`, `plan`, any other mode, and any other or caller-set feature are refused. When pace recovers, new lanes resolve Opus; recorded lanes keep their route. Nothing else moves: PMs, owner-named routes, every other class (`review-security` and all reviews included), lanes with a recorded route, running agents, and excluded launchers, listed locally, with anything they launch (the launching `PASEO_AGENT_ID` and its parent chain are checked; an unreadable list or chain allows no off-pace route).

Off-pace backup (owner decisions 310 and 316): only with evidence that Neon cannot launch (newer than any fresh proof) does the lane run Pi `fleet/gpt-6.2-sol` at medium, Fast off (owner 2026-11-21), source `pace-backup`. A missing proof is not that evidence: off pace with neither a proof nor evidence stays Opus. It is the only GPT route a `code` lane may take: it records only while off pace through this admission, launches only from its own recorded lane, and every other GPT code route is still refused. A recorded lane never changes route, so after a Neon failure resolve a new lane with the evidence.

The switch is `antigravityFallback: {enabled, state: {off_pace, as_of, expires_at}}`, written only by Config's pace job. It is on only with both booleans true, RFC 3339 UTC times with `as_of <= now < expires_at`, on a Mac, in a regular file owned by the user and writable only by them, with no repeated key. Absent, false, stale, unknown or unsafe stays Opus, as does a missing or malformed local list of excluded launchers. Config owns `expires_at`; OPC sets no cap. Never copy its values into a reason, brief, record or log.

Invocation: pass `replacement: {task, lane, proof, target}` (Neon) or `{task, lane, target, unavailable}` (backup) to `resolveWorkerRoute` and `recordWorkerRoute`; `route.mjs --class code --task T --lane L` passes only `{task, lane}`, so it stays Opus. For Neon, call MCP `create_workspace`, then MCP `inspect_provider` for `agy-opc` on that workspace's server with the draft `settings: {modeId: 'auto', model: 'gemini-4-neon-high', thinkingOptionId: 'high', features: {auto_accept: true}}`, and MCP `list_models` for `agy-opc`. Pass `capabilities: {...inspect_provider result, models: list_models rows}`, `target`, and the unchanged `create_workspace` result as `workspace` to `buildManagedWorkerRequest`, with no `provider` or `agentSettings`. The backup launches like any Pi Worker.
- `target` `{daemon, local: true, platform: 'darwin'}`: the local daemon; `daemon` is the `serverId` that `create_workspace` returns.
- `unavailable` `{provider: 'agy-opc', target, checked_at, finding}`: what MCP `inspect_provider` and `list_models` showed on that target within the last hour, `finding` one of `missing`, `disabled`, `not-available`, `not-serving` (not the model at high with mode `auto`).
- `proof` `{provider, extends: 'acp', model, thinking, mode: 'auto', sandboxed: true, write: true, target, verified_at}`: the PM's attestation from a readback on that target within the last hour (the approved `agy-opc` row and a proof agent's status showing this runtime). Keep no raw snapshot or switch state.

The code enforces exact equality of these fields with the approved runtime; re-admission at recording; and at every launch and rebuild, that the record is exactly its approved runtime, that the workspace's `serverId` is the recorded target, that `inspect_provider` reports `agy-opc`, the model at high, mode `auto` and one `auto_accept` toggle set true, and that the request sends exactly those settings. These gates are bookkeeping, not a sandbox; the owner accepted that agy's sandbox may write outside the repository. The receipt binds task, lane, target and placement (the branch), never the switch state. A recorded off-pace lane resumes (`route.mjs --task T --lane L`, no route flags) and rebuilds on its route without reading the switch; if the record or the target no longer matches, the lane stops.

## Errors

Network and proxy errors, such as `Connection error` or a 502 `backend unavailable`, are retried on the same route by sending the same Worker a continue follow-up. They never change the model or effort. Rate limits, unavailable capabilities, and real launch failures still stop the lane; substitution requires a new explicit owner decision.

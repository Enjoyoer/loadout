# cache-aware-autocompact

Server-only Paseo plugin for Paseo >=0.10.3 <0.12.0, built against the exact 0.11.1 `@getpaseo/*` packages. It starts one timer per completed Claude, Codex, or supported Pi turn and, after a configurable cache-preserving delay, evaluates the latest idle snapshot. The default is **dry-run**: it logs `would-compact` decisions and never sends anything. Only `config.armed=true` permits a `/compact` send.

## Design

- Claude default delay: 50 minutes, based on the documented 1-hour subscription TTL with a 10-minute margin.
- Codex default delay: 22 minutes, based on the documented 30-minute cache lifetime with an 8-minute margin.
- The only boundary check is a running tool call. Open todos, a missing final answer, and open-ended or coordination wording never block compaction; the summary preserves open questions. `softThreshold` (300,000 tokens) now only labels the decision `safe-boundary-recall` in logs. `thresholdTokens` remains the minimum context usage for any compaction.
- Timers are canceled on `agent.turn_started`, an agent update showing a running/active turn, archive, cleanup, or a changed `lastUserMessageAt` at evaluation time.
- Pi chooses the cache family from the refreshed snapshot's actual model: `fleet/claude-*` uses `claudeDelayMinutes` (50 minutes by default). `fleet/gpt-*` idle compaction is **off by default**, logged as `pi-gpt-disabled`. Set `config.piGptEnabled=true` to opt in after measuring cache costs; enabled GPT Pi uses `codexDelayMinutes` (22 minutes by default). Native Claude and Codex defaults are unchanged. Recovery and evaluation use the same enabled family for the reference TTL. Missing/unknown models and ChatGPT web routes are skipped as `unsupported-pi-model`; their cache policy is not established. Picker labels, thinking level, and service-tier labels do not select the delay.
- Guards fail closed: provider is `claude`, `codex`, or `pi` with a supported fleet model; agent is idle with no active turn; no pending permissions; `attentionReason` `finished` or null is allowed, while `permission`, `error`, and unknown values block; context usage is at least 100,000 tokens by default via configurable `thresholdTokens`; label `autocompact=off` is absent; no tool call is still running. Failed or canceled tool calls never block compaction.
- A `running-tool` or `not-idle` evaluation skip is retried after two minutes, up to three retries, so a busy agent can compact after it settles.
- The safe-boundary classifier is deterministic and local. No transcript is sent to a classifier service.
- On startup, the plugin enumerates all agent directory pages and re-arms eligible idle agents. It repeats recovery on the first hook subscription and on connection snapshots, including reconnects. An existing timer is kept, so repeated snapshots do not postpone it.
- Recovery skips agents whose ended turn is at least the reference cache TTL old (**60 minutes for Claude, 30 minutes for Codex**, including the corresponding Pi fleet routes), counted as `cache-expired` in `rearm-summary`, without scheduling a timer. Warm agents use `max(0, configured delay - elapsed idle time)`. Timers already due but still within the TTL keep independent random jitter between **2 and 7 seconds**, defined by `REARM_JITTER_MIN_MS` and `REARM_JITTER_MAX_MS` in `server/recovery.ts`. Evaluation checks cache age again, including immediately before sending: late timers and retries crossing the TTL are terminal `cache-expired` skips and never compact a cold agent. Re-arm, reconnect, and restart cannot trigger a burst of cold-agent compactions.
- Each observed turn end now persists its original checkpoint key, running-tool guard state, last user message timestamp, and exact end time. Full transcripts are not retained in this turn metadata. For turns completed before this version, Paseo 0.9.2 has no `lastTurnEndedAt` snapshot field: recovery uses the finished-attention timestamp, or the last persisted timeline timestamp if attention was cleared. The latter can precede the actual turn end. Empty history without stored turn metadata, or unavailable history, is skipped with a reason.
- Durable state is stored at `$PASEO_HOME/plugin-state/cache-aware-autocompact/state.json`. Checkpoint keys include agent and turn identity, so duplicate lifecycle delivery cannot send twice. Terminal decisions, including dry-run and failed attempts, are not re-armed. Retry decisions retain the bounded retry count across restarts. State read errors fail closed. A `compact-requested` checkpoint is written before sending, so a restart cannot resend a reserved turn even if send acknowledgement was lost. A crash after reservation but before delivery can leave that turn unsent; recovery deliberately treats the reservation as handled.
- A send acknowledgement is **not** compaction success. The plugin waits for the turn to settle, then requires a new completed compaction timeline row with no compaction error/cancellation output. Pi can emit a synthetic completed row before reporting an error, so error output takes precedence. One window, `compactionWindowMinutes` (default 20 minutes, measured from the send), covers the settled-turn wait and the wait for the completed row, because a large summary under load can take well over five minutes. A settled-turn wait that ends in `timeout`, `error`, or `permission` is logged as `wait-for-finish`. A plugin reload inside the window cancels the observation, and the stopped instance logs `compaction-abandoned` and writes no state. When the window ends with neither a completed row nor error output, the plugin looks at the timeline once more and records `compaction-unconfirmed`, not `compaction-failed`: a summary that is only slow is not reported as an error. Errors and unconfirmed results are backed off durably until the next real user turn, not automatically re-sent every timer period. An automatic `/compact` user row does not clear backoff. The original `attemptedAt` request time is retained so a real user turn racing a late failure can still re-arm. Automatic compact turns are not re-armed; a concurrent real turn is deferred until the attempt finishes. A new real user timeline timestamp must follow the request time; missing user history stays backed off rather than trusting a snapshot timestamp that might belong to `/compact`. Older state uses its recorded creation time.
- The action is `agent.send("/compact")` to the one freshly refreshed idle agent. Paseo resolves this to Claude's root slash command, Codex's manual compaction path, or Pi's native compact RPC. On Paseo 0.10.3 and 0.11.1 (unchanged), `PiRpcAgent.tryHandleOutOfBand` invokes `executeCompactCommand`, which calls `runtimeSession.compact()` and sends `{type:"compact"}` over Pi's RPC protocol. It does not send `/compact` as an LLM prompt. Calling Pi's raw prompt RPC with a slash command is not the path this plugin uses.
- A disposable Paseo 0.10.3 daemon with a credential-free Pi RPC fixture verifies the native action path using accelerated scheduler timers with the production 50-minute Claude and opt-in 22-minute GPT configuration. GPT is skipped by default, and web routes never compact. A failed native Pi compact RPC is not re-sent across plugin reloads until a real user turn. The fixture starts disarmed, pins a distinct home and explicit endpoint, checks the plugin's own connection identity and fixture-only directory before arming, and verifies the scratch port is clear before launch and after shutdown. Unit tests cover defaults, recovery, guards, synthetic completed rows followed by errors, cancellations, restart backoff, and a real user turn racing a late failure. The 0.11.1 build was rerun on disposable 0.10.3 and 0.11.1 daemons with a 1-minute test delay: each sent exactly one native Pi compact RPC for the Claude route and recorded `compacted`. These are protocol/action proofs, not measurements of real provider compaction quality or cache retention.

The safe-boundary ideas are informed by [kunchenguid/compact-adviser](https://github.com/kunchenguid/compact-adviser), which is MIT licensed: classify a finished unit and avoid open-ended coordination. This plugin uses a local rules implementation and does not copy its code or send data to its service.

## Restart logs

The plugin opens a persistent SDK connection at startup because Paseo 0.9.2 supplies the hook SDK only after a lifecycle event. It uses a valid explicit `PASEO_HOST`, then the local daemon listen address in `$PASEO_HOME/paseo.pid` (also the runtime metadata location in Paseo 0.10.3). An explicit non-default `PASEO_HOME` without valid endpoint metadata **refuses to connect**, including while the supervisor's listen address is still null during startup. Set an explicit TCP `PASEO_HOST` or wait for a later hook connection rather than connecting to a different daemon. The standard local CLI address is a fallback only when the home is unset or equals `~/.paseo`. Invalid explicit hosts also refuse fallback. Cleanup aborts subscriptions, closes that connection, and cancels timers.

Each recovered timer emits one JSON log line with `action: "re-armed"`, `agentId`, `provider`, `idleSince` (UTC timestamp), `remainingMs` (delay before jitter), `delayMs` (scheduled delay), and `jitterApplied`.

The first completed recovery pass emits `action: "rearm-summary"` with `trigger`, `rearmed`, `skippedCount`, and `skipped` counts grouped by reason. Later passes emit a summary only when they re-arm an agent or their skip counts change, ignoring `already-pending` when comparing counts. Logged summaries still include all skips. Reasons include `cache-expired`, `not-idle`, `unsupported-provider`, `opted-out-label`, `archived`, `checkpointed`, `already-pending`, `cwd-missing`, `no-ended-turn`, `timeline-unavailable`, `changed-during-recovery`, and `recovery-failed`. Missing working directories (`ENOENT` or `ENOTDIR` from `lstat`) are counted as `cwd-missing` before fetching the timeline.

Connection or recovery failures emit `startup-rearm-failed`, `subscription-failed`, or `rearm-failed` with a reason. Within one plugin process, each distinct recovery error message is logged once per agent. Repeated errors are still retried on recovery passes and counted as `recovery-failed` in summaries. Successful recovery or a new turn clears that agent's failure cache. Re-armed timers still emit the existing evaluation, retry, and cancellation logs. An evaluation with unknown context usage now logs and records `context-unknown`; it remains a terminal skip with no retry, just like the previous `context-below-threshold(unknown)` reason.

## Research sources

- Paseo 0.9.2 Claude provider: [`CLAUDE_ROOT_ONLY_COMMANDS` includes `compact`](https://github.com/getpaseo/paseo/blob/v0.9.2/packages/server/src/server/agent/providers/claude/agent.ts#L363-L374), and [`resolveSlashCommandInvocation`](https://github.com/getpaseo/paseo/blob/v0.9.2/packages/server/src/server/agent/providers/claude/agent.ts#L2799-L2810) recognizes `/compact`.
- Paseo 0.9.2 Codex provider: [`tryHandleOutOfBand("/compact")`](https://github.com/getpaseo/paseo/blob/v0.9.2/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L4975-L4995) calls [`thread/compact/start`](https://github.com/getpaseo/paseo/blob/v0.9.2/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L5012-L5037). The provider parses the [`thread/compacted` notification](https://github.com/getpaseo/paseo/blob/v0.9.2/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L2685-L2698) and correlates manual completion with `pendingManualCompactionStarts`.
- Paseo 0.9.2 lifecycle contract: [`agent.turn_started`, `agent.turn_ended`, and permission hooks](https://github.com/getpaseo/paseo/blob/v0.9.2/packages/plugin/src/server/lifecycle.ts#L47-L65).
- Claude Code costs: [prompt cache statistics and cache lifetime](https://code.claude.com/docs/en/costs). The current docs say the lifetime is **one hour on a subscription**, **five minutes when using usage credits**, and **five minutes by default on an API key or cloud provider**. The [Anthropic prompt caching API docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#ttl-support) document 5-minute default and optional 1-hour API TTL.
- Codex/OpenAI: [Prompt caching, cache lifetime](https://developers.openai.com/api/docs/guides/prompt-caching#cache-lifetime) documents a **30-minute** default minimum lifetime for current GPT-5.6-and-later models. CLIProxyAPI's [README](https://github.com/router-for-me/CLIProxyAPI) describes protocol-compatible routing but does not specify a separate cache TTL; the upstream Claude/OpenAI account and request options therefore govern TTL.
- Reference classifier: [compact-adviser README](https://github.com/kunchenguid/compact-adviser#how-it-works) and [MIT license](https://github.com/kunchenguid/compact-adviser/blob/main/LICENSE).

## Verify and install later

This work intentionally does not install, reload, enable, disable, arm, or restart anything.

```bash
cd plugins/cache-aware-autocompact
npm ci
npm run check
```

When the owner chooses to install in dry-run mode, use `paseo plugin install "$PWD"` and review `paseo plugin logs cache-aware-autocompact`. Leave the settings file absent or set:

```json
{"version":1,"values":{"armed":false}}
```

The plugin starts disarmed even when the settings file is absent. Do not write `armed: true` unless the owner separately approves arming.

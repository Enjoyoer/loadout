# Paseo 0.14 compatibility review

Reviewed 2026-10-29. All seven plugin upper bounds move to `<0.15.0`; lower bounds and npm dependency pins stay as they were. Two plugins need one shared implementation adjustment: recognize 0.14 heartbeat timeline rows as turn inputs. This review authorizes no production daemon upgrade.

## Inputs and method

- [0.14 release notes](https://github.com/getpaseo/paseo/releases/tag/v0.14.0).
- Upstream git comparison: `v0.13.0` (`d34d17a9072149320ace35ec2a2e5c7dcd992cb3`) to `v0.14.0` (`8c6de842a3157530c26a7a94c78a3d647fb96ce9`). Reviewed server lifecycle/loading, creation, workspace/archive, message delivery/receipts, timeline projection/paging, schedule, provider configuration, persisted config and speech changes, plus plugin/client/protocol contracts.
- npm `@getpaseo/{server,cli,client,plugin,protocol}` at both versions. There is no published `@getpaseo/app@0.14.0`; downloaded the matching desktop release archive instead, unpacked `app.asar`, and read its package metadata: `@getpaseo/desktop` 0.14.0. `artifacts.json` records hashes and byte-equality comparisons. Minified/generated bundles were compared by SHA256 and bytes, never text diff.
- Read the deployed plugin quickstart, reference and publishing pages, then checked the release-tag source for exact 0.14 behavior.
- Installs, builds, existing suites and live daemon checks ran through the Linux build gate in scratch directories. Both speech features were explicitly disabled; relay was disabled; daemons listened on separate ephemeral loopback ports and used separate homes. Shutdown targeted the scratch daemon object in its own process. No production service management command was run.
- Live checks use the published server and real WebSocket, plugin subprocess, compiler, settings and MCP paths. Provider sessions use the upstream fake-agent client with synthetic catalog entries, usage and quota failures. They make no model requests. This isolates daemon compatibility from subscription and provider availability.

### Common contracts and fields

- Manifest: `id`, optional `description`, `requirements.paseo`; optional `index.server.ts` and `index.client.tsx` entry conventions. Only pi-fast-toggle has a client entry. npm package versions are separate from the plugin compatibility range. Each plugin keeps its old dependency floor so it can still bundle against the supported older SDK.
- Server registration, callback context, cleanup, RPC validation and host-scoped settings are preserved. Settings definitions remain: archiver/sweeper/autocompact `config` v1, auto-resume `auto-resume-config` v2, Fast `routing` v1. Each plugin's complete field allowlist and defaults remain in its `server/config.ts` or `shared/contracts.ts`. 0.14 still uses `<PASEO_HOME>/plugin-settings/<plugin>/<settings>.json` with `{version,values}`. No setting is renamed.
- Target resolution remains `PASEO_HOME`, explicit `PASEO_HOST`, then that home's `paseo.pid.listen`, with a default endpoint permitted only for the default home. Pi mutations require the local daemon's own recorded loopback endpoint. 0.14 still supplies the correct subprocess home; live plugin connections resolved the scratch daemon.
- Archiver workspace fields: `id/name/projectId/projectDisplayName/projectRootPath/workspaceKind/workspaceDirectory/worktreeSlug/status/archivingAt/activityAt/statusEnteredAt/createdAt/lastUserMessageAt/setupStatus/pinnedAt/labels/background/scripts[{scriptName,lifecycle}]/gitRuntime.{currentBranch,isPaseoOwnedWorktree}`. Agent fields: `id/workspaceId/status/title/labels/pendingPermissions/requiresAttention/attentionReason/attentionTimestamp/createdAt/updatedAt/lastUserMessageAt/archivedAt`. Terminal fields: `id/workspaceId/cwd`. Project fields: `projectId/projectDisplayName/projectRootPath`. Page cursors, `hasMore/nextCursor`, `includeArchived` and `includeBackground` retain their meanings.
- Recovery snapshots: `id/workspaceId/provider/model/cwd/title/status/activeTurn.{turnId,startedAt}/currentModeId/thinkingOptionId/runtimeInfo.model/effectiveThinkingOptionId/lastError/pendingPermissions/requiresAttention/attentionReason/archivedAt/lastUserMessageAt/updatedAt/labels/lastUsage/persistence.{provider,sessionId,nativeHandle,metadata}`. The compaction decision reads `lastUsage.contextWindowUsedTokens`; metrics retain the whole usage record. These fields retain their meanings; unsupported/missing values still fail closed. Fast additionally uses `opc.service-tier` and `opc.fast-requested`; recovery and cleanup retain their existing opt-out/parent/project labels.
- Timeline contract: entries carry `item` and paging cursors; user message text and message/client IDs, assistant text, tool name/callId/status/error/detail/agentMessage, error rows, and completed compaction rows remain available. Turn outcomes and permission lifecycle events retain their existing shapes. 0.14 adds optional whole-turn paging; these plugins do not request it, so their existing item/cursor walking remains in use.
- The recovery plugins' `kill_agent` and Fast plugin's `update_agent` use JSON-RPC `tools/call` on `/mcp/agents`, accepting JSON or SSE responses. These routes and response success/error handling are preserved. Password-protected daemons can still refuse a credentialless plugin mutation; no authentication setting is changed.
- Receipts: `<PASEO_HOME>/agent-requests/*.json` still contain `agentId`, `state` (`pending/completed`) and fingerprint, with atomic replacements; archiver uses file mtime for delivery activity. Idempotent sends still use `messageId`. Live sends created receipts. No receipt reader schema change.
- Managed worktree metadata still lives at `<git-dir>/paseo/worktree.json`; archiver reads `baseRef/baseRefName`. The 0.14 async filesystem refactor retains those fields and layout. - Durable agents still live at `<PASEO_HOME>/agents/<project>/<agent>.json` with legacy top-level records readable. Auto-resume reads `id`, `config.model`, `config.thinkingOptionId`, `labels.opc.service-tier`. Plugins retain their own `plugin-state/<id>/` state/ledger/metrics formats.
- Fast's private overlay reads `runtime.json` (`python`, `credentialHeaders`, `paseoMcp.url`), `agent/models.json` (`providers`, provider/model API/base URL, exact model IDs), invokes `credential.py`, and checks the router model catalog's `id/slug/service_tiers[].id`. Peer routing uses SSH and a typed client; optional quota polling uses `pq`; history fallback has no provider CLI hook. All actual daemon control in this review is scratch-only.

## Semantic changes requiring attention

1. **Heartbeat timeline input, fixed here.** [0.14 envelope projection](https://github.com/getpaseo/paseo/blob/v0.14.0/packages/server/src/server/agent/agent-messages/envelope.ts) converts `<paseo-system>` prompts into completed `heartbeat` tool rows with `paseo-system:<sha256>` call IDs and plain-text detail. The old helper recognizes only user messages and `agent_message` tool rows. On a live 0.14 failed heartbeat, the old helper returned no input. The updated helper recovers the body and stable ID, allowing the retry to bind to the right turn and supersede older work. Other tool rows remain excluded. 0.13 user/agent-message handling is retained. Its hidden system-envelope rows remain hidden; the 0.13 live run exercises the original user-input retry path.
2. **Idle runtime collection.** 0.14 defaults `agents.idleRuntimeCleanup` to true: eligible idle, persisted, non-internal runtimes can close after one hour, with parent-family, pending-work and provider veto checks. This emits the ordinary `agent.closed` event and saves the session for reopening on a prompt. Existing close guards still apply; an operator should expect more closed snapshots. Cache timers normally run before that hour. The isolated main-path checks disable this setting to keep runtime collection separate from plugin behavior; no hour-long collection experiment is claimed.
3. **Session-open hooks are additive.** Requests gain `title`, readonly `labels`, `tools` and mutable `mcpServers`; history fallback only reads its existing fields and returns no rewritten request. Plugin loading/reload can invalidate sessions so the next operation reruns hooks. No plugin introduces tools or launch-time MCP changes here.
4. **Compiler work moves off the daemon thread.** Server/client entry boundaries and host modules are preserved. All seven compile and load concurrently in the plugin catalog. The client SDK contribution APIs used by Fast have no relevant signature change in the tagged diff.
5. **Send/steer and archive semantics.** The additive session reload API is distinct from snapshot `refresh`; plugins continue using `refresh` only for reads. `steer`, fixed message IDs, background inclusion and managed-worktree archive ownership remain available. Existing race and close-restoration suites pass against 0.14 types as well as the original pins.

Relevant [0.14 persisted schema/normalizer](https://github.com/getpaseo/paseo/blob/v0.14.0/packages/server/src/server/persisted-config.ts):

- `features.voiceMode.enabled` now defaults to false when absent; dictation still defaults to true. An existing explicit voice true stays true.
- Connection fields belong under `features.dictation.stt`, `features.voiceMode.stt` and `features.voiceMode.tts`, selected by provider. Voice LLM remains `features.voiceMode.llm.{provider,model}`.
- Legacy `providers.openai` is folded/discarded at the file boundary. `providers.local.modelsDir` remains supported. Legacy `providers.local.autoDownload` is stripped; it is not a download-disable switch.
- Provider-discriminated validation drops irrelevant legacy speech knobs: local STT `confidenceThreshold`, local TTS `voice`, OpenAI TTS `speakerId/speed`. Unknown remaining fields still fail strict validation.
- `agents.providers` remains the provider-picker/launcher configuration and is distinct from the root speech `providers`. No new provider rename is needed. Existing legacy-provider normalization remains present.
- Speech model management adds local-model list/download/delete RPCs. The [speech runtime](https://github.com/getpaseo/paseo/blob/v0.14.0/packages/server/src/server/speech/speech-runtime.ts) can download missing models for enabled local speech automatically. Leaving dictation absent does not prevent downloads. The zero-download result here applies to explicit disabled features, not default-enabled dictation or enabled voice.
- Startup also removes the obsolete `agent-timelines` directory. Plugin state, receipts, worktree metadata and agent profile layout are not migrated by this release. A config backup alone is not a full data rollback snapshot.

## Validation and limits

`checks.json` records each final existing plugin check with original dependency pins and with scratch-only 0.14 replacements: 322 existing tests pass in each dependency set, plus all seven typechecks and six defined builds. History fallback and workspace title have no test script. `live-final-0.14.0.log` and `live-final-0.13.0.log` record the final socket/subprocess checks. Cleanup dry-run logs retain the decision reasons; `plugin-events.log` retains selected hook/timer/retry records. Logs are sanitized to synthetic identifiers and scratch placeholders.

The dependency replacements are validation-only and are not committed. The full repository suite also passes: 249 tests, two existing skips, plus manifest, package, vendored-helper, raw-write and daemon-target checks. Its first run had two fixture command-name false positives because the scratch pathname itself contained `paseo`, and a transient empty-output failure in the existing process-recovery case. The 26 sync cases passed with a neutral fixture temp pathname, the recovery case passed independently, and the full unchanged suite then passed with that fixture temp root. See the three `repo-*-recheck` / `repo-tests-final` logs. No permanent test suite was added. The live fixtures check transport, hooks, canonical timeline interpretation, settings, real Git worktree metadata and plugin main paths; they do not establish real provider startup timing, live subscription quota behavior, cross-host SSH health, native speech quality, or desktop/mobile appearance. Those existing deployment-specific limits continue to apply.

## Rollout and rollback notes for the configuration owner

- Stage the plugin patches before the canary daemon upgrade, so the 0.14 heartbeat input path is ready. Plugin source changes need plugin reload, not a production daemon restart by this worker.
- Back up the full 0.13 home and byte-exact `config.json` before the canary. Preserve that backup until downgrade risk has passed. Include provider launcher/runtime files in the operational snapshot.
- Explicitly choose dictation and voice feature flags before starting the canary. For a no-download canary, set both false. Move environment-only legacy OpenAI connection fields into explicit speech use sites before relying on them, using the normal credential-handling workflow.
- Review the one-hour idle cleanup default. It is a new lifecycle behavior even though the existing status/event contracts remain valid.
- If rolling back after any 0.14 settings save, restore the backed-up 0.13 config before starting the old server. Do not feed the saved per-site speech credentials or `agents.idleRuntimeCleanup` to 0.13. Restore the home snapshot if data rollback is needed.
- This PR is not merged by this worker. Actual canary and subsequent host upgrades remain with the configuration owner.

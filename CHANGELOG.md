# Changelog

All notable changes are listed here. Loadout follows [semantic versioning](https://semver.org).

## Unreleased

### Added
- Fleet `bin/` folder: the skills sync installs private helper scripts into each host's user bin.

### Changed
- browse-x requires an explicit API endpoint from environment variables or a user config file; no queries go to an implicit third-party proxy.
- OPC 7.49: remove the owner approval gate, task fields, and approval command; delivery no longer requires an owner approval step. Worker routes still reject reviewer-only web models.
- OPC 7.48: Fable is a one-time UI pass, at most one `ui` lane per task; surrounding code and rework go to a separate `code` task.
- OPC 7.47: browser and computer-use lanes run on native Codex with Paseo browser tools (same models, Fast on).
- Example global instructions gain a Secrets section.
- `wo`: no separate prompt file; the skill is the slash entry (`/wo`, Pi `/skill:wo`).
- OPC 7.44: browser and computer use default to Sol medium; Astra is the `browser-hard` escalation.
- OPC 7.43: seven Worker classes with legacy aliases; Opus keeps code, Fable high handles UI, Sol plans and reviews, Astra browses, Luna runs smokes and watchers, and every GPT lane has Fast on (owner 2026-10-13).
- OPC 7.42: code, code-bounded, test-fix and automation lanes range up to Opus xhigh, and a lane with any UI work is the ui class.
- Pi routing: the chatgpt-web environment context is a current-turn user item directly before the instruction, as Codex sends it, so the gateway no longer also reads the system prompt's real cwd and rejects the turn for conflicting cwd values.
- Pi routing: chatgpt-web requests send `/workspace/<folder>` as cwd and workspace root instead of the bare folder name, which the gateway rejected as not absolute (every Web turn failed since the 10/09 change).
- personal-skills: an optional `pi.contextWindows` map sets Pi's context window per canonical label (API entries included), so Pi's context meter and compaction trigger match a backend's effective cap.
- OPC cloud briefs tell the session its container can restart and lose unpushed work: push a first small commit and open the draft PR before other work, then push after each completed step; the launcher follow-up says the same after a restart with nothing pushed.
- `frontend-design` is now Anthropic's official frontend-design skill, copied unmodified from the official Claude Code plugin; the skill name is unchanged.
- `merged-worker-archiver` caps archives per sweep again (`maxArchivesPerSweep`, default 5; the rest are deferred to the next sweep) and treats git-ignored files in a worktree as dirty, so an ignored `.env`, local notes, or `node_modules` now block archival.
- `cache-aware-autocompact`, `merged-worker-archiver`, `orphan-project-sweeper`, and `usage-limit-auto-resume` now share one fail-closed daemon endpoint resolver. Its canonical source is `plugins/_shared/daemon-target.ts`, each plugin vendors a byte-identical copy, and CI fails when a copy drifts. Endpoint resolution is unchanged.
- OPC test recovery records the cleanup of a test command whose pid another process now holds as `cleanup incomplete: PID reused` (was `incomplete: PID reused`).
- OPC 7.39: PMs split separable outcomes into parallel Worker lanes, one owner per file; a shared live resource serializes only live checks.
- OPC 7.40: every route, owner-named included, resolves through the routing tool, and OPC states that Pi has Fast on GPT routes.
- OPC 7.41: cloud lanes are removed; every Worker runs locally on its normal route. The code is in git history.
- The `claude-cloud` skill is deprecated and no longer published or synced; its source is in `deprecated/claude-cloud`.

### Fixed
- OPC 7.48.1: Worker routes reject reviewer-only web models, including catalog aliases and explicit native providers.
- OPN: worker option uses `gpt-6-luna` (was the retired `gpt-5.6-luna`).
- OPC 7.46: Codex Sites route uses `gpt-6-luna` (was the retired `gpt-5.6-luna`).
- OPC PR evidence is published from a detached worktree with `git push origin HEAD:pr-evidence`, instead of `git worktree add -B`, which reset a local `pr-evidence` branch and dropped evidence commits never pushed; such commits are carried over first, and a rejected push is rebased and retried before the worktree is removed.
- `claude-cloud` records a launch as `launching` in the project's `STATUS.html` before the session command and as `uncertain` when the command or capture fails or is ambiguous; such a launch is reconciled against the marker's PR and claude.ai/code, never repeated, and only a confirmed `no session` permits one new launch. Under OPC it defers to the cloud lane's intent and reconcile calls.
- OPC `delivery.mjs test` no longer waits forever after SIGINT or SIGTERM for a test command that ignores the signal: the command's group gets 10 s, then is killed under the same start-time identity rule as recovery and gets 10 s more to close. The `blocked` receipt records the `cleanup` outcome, `cleanup incomplete: did not exit` when the command still has not closed, and keeps the command's pid and start time; when the rule forbids the kill, the controller stops waiting and says so.
- OPC test receipts fingerprint the working-tree bytes of submodules and untracked nested repositories, recursively, instead of one directory entry, so a test that changes a file inside an already-dirty submodule no longer records `passed`, and a receipt is not reused across different dirty submodule contents. A gitlink in the index whose working tree is not a real directory with its own `.git` (missing, uninitialized, or reached through a symlink) fails the receipt with that reason.
- OPC task updates sync the new `task.json` before the rename and, on POSIX, its directory after it before returning, so a cloud launch intent that authorized a session command survives an OS crash or power loss there. Windows gets a flushed file and an atomic rename only.
- OPC task locks are never reclaimed implicitly. A lock is published already holding its writer's pid, start time and a unique token (a hard link to a finished file); the writer checks its token before replacing `task.json` and releases only a lock that holds it. A writer that finds a lock fails after 2 s with `task lock busy`, naming the holder and the recovery command, and `task-state.mjs unlock <task.json>` removes a crashed writer's lock only when its pid is gone or reused. The automatic reclaim of a dead holder's lock, its reclaim marker, and the 10 s empty-lock reclaim are gone: they could remove a live writer's lock and allow two cloud launches.
- OPC delivery is blocked by any non-author reviewer's current exact-head `CHANGES_REQUESTED` review when the recorded web review approved that head, not only when review was unavailable.
- `cache-aware-autocompact`, `pm-native-worker-guard`, and `usage-limit-auto-resume` state writes survive a host crash on Linux and macOS: the shared atomic writer flushes the state directory after the rename before it resolves, and on its first write to a directory it also flushes each parent it may have created; an unexpected error checking or flushing one rejects the write. On Windows the rename is not flushed, so a host crash soon after a write can bring back the previous state.
- The state readers of `cache-aware-autocompact`, `pm-native-worker-guard`, and `usage-limit-auto-resume` reject a malformed record (a missing id, an unknown state or outcome, an unparseable time) through their fail-closed unreadable-state path instead of acting on it.
- `pm-native-worker-guard` records a PM notice as `sending` before it goes out. A notice whose outcome cannot be recorded is never sent again (`notify-unrecorded`), and one that cannot be reserved waits for the PM's next turn end. Concurrent first state reads share one read, so a slow read cannot roll back a newer write.
- `cache-aware-autocompact` takes a running tool call's status from fresh history on each retry, so a tool that completed, failed, or was canceled after its turn ended no longer blocks compaction until the retries run out. A tool call with a status the plugin does not know counts as running, and a remembered turn must hold only running tool calls with a call id.
- `pi-fast-toggle` sends its label update only over `http` to the MCP endpoint at the listen address its own daemon recorded in `paseo.pid` under the plugin's `PASEO_HOME`, and refuses redirects. Without that record it writes nothing and reports why; `PASEO_HOST` and the default address do not count.
- `cache-aware-autocompact` and `usage-limit-auto-resume` keep state and metrics under `PASEO_HOME` or the user's home directory, as the daemon resolver does, instead of `HOME` with a `/tmp` fallback.
- `usage-limit-auto-resume` rolls back a send refused with `Transport not connected` from the stored record, undoing only what the claim set. A turn that started during the send, even one the turn-start handler has not stored yet or one that arrives while the rollback is being written, turns the record `uncertain` with its turn ID, deadline and attempt kept, instead of re-arming a duplicate send.
- `usage-limit-auto-resume` claims a record for a send only while it is unchanged since the send checks, at the same attempt count. Until the message is handed to the daemon, a permission request, an archive, or any turn that starts or ends on the agent cancels the send, and that turn is never taken as the resume's. The agent is read again right before sending, and a newer user message, a turn change or a failing send check cancels it. A send receipt no longer turns a terminal state back into `verifying`. A resumed turn still running at the next poll is no longer superseded by the plugin's own message, and failed retries keep their backoff and attempt count. The state file never prunes a record that can still act or is `uncertain`. It keeps at most 200 settled records, plus a guard (agent, source turn, persistence session) for up to 2000 pruned ones, so a repeated turn event stays a duplicate. Sweeps re-read the file only for actionable records, and failed-turn records keep their 20 newest attempts.
- `orphan-project-sweeper` no longer treats a non-empty parent as proof of a mount. On Linux and macOS every mount point `/etc/fstab` declares over a project root must be mounted; on Windows no existing ancestor may be a junction, symlink, volume mount point or non-directory, and a parent or drive root that cannot be read, or is not a directory, is unverifiable rather than missing (`mount-absent` and `mount-unverifiable` skips). The root, parent and mount checks run again immediately before `removeProject`.
- `merged-worker-archiver` no longer archives a worktree whose submodule directory is not empty (`submodule(path)`): the superproject's `git status` cannot vouch for a submodule's changes or ignored files, nor see files in an unpopulated one. An empty, unpopulated submodule directory does not block; a symlink or junction in its place, a submodule path that is not UTF-8, or a git top level that does not resolve to the workspace directory, does. Its git calls drop inherited `GIT_*_PATHSPECS` modes.
- `orphan-project-sweeper` aborts a sweep or re-check when the daemon's workspace listing is incomplete (more pages without a cursor, a repeated cursor, or more than 50 pages) instead of counting a project's active workspaces from part of it, and an archive re-check whose `removeProject` fails or whose final check changed keeps its remaining attempts.
- OPC test recovery tells a reused pid from the recorded process by its exact start time, read in one fixed format, and stops the test command's process group, on POSIX even after its leader exited; a pid reused by another process is never signalled and the record says the cleanup is incomplete. Windows uses `taskkill /T /F`, which cannot reach a descendant orphaned after its parent exited. Task locks record their holder's start time; a live holder whose start time cannot be read keeps its lock.
- OPC relaunches a recorded Worker lane (repair, restart) after a class-table change. Given the task record, lane and lane class, the Worker request and brief take only the lane's recorded route and rebuild it while it keeps the owner's rules for that class, whatever its recorded source: code classes never run a GPT or web model, `ui` is exactly Opus xhigh with Fast off, and no route runs below its class minimum. A task default also keeps its class's model and Fast, at any effort up to the class ceiling that the Pi catalog still serves. An explicit provider must be the one the validated route maps to, and `route.mjs` refuses route flags that would select another route for a recorded lane.
- OPC records a cloud lane as launching before the session command runs, and `recordCloudLaunch` only completes that record. An uncertain launch is settled with `reconcileCloudLaunch` or `cloud-lane.mjs reconcile <task.json> --session <id> --url <url>` (running) or `--no-session --reason <text>`, which permits one relaunch.
- Fleet push writes the fleet copy and its `.loadout-sync.json` through uniquely named, exclusively created temp files and reads the record back, so a planted `<file>.loadout-tmp` link can no longer redirect a write; a leftover temp name is skipped only when it is a regular file.
- Fleet push, skills sync, and plugins sync check each write and removal again right before it: the directories from the home directory down (a linked `~/.claude` or `~/.config` is refused) and the file itself. A file edited after preflight is not written over, and a removal moves the file aside and verifies it first, so an edit made meanwhile is kept and the host fails.
- Fleet push and skills sync record the versions a run is about to write as pending before writing, and skills sync also accepts a skill file's last synced version, so a run or controller cut off part way no longer turns its own writes into conflicts.
- Skills sync installs private overlay files owner-only on macOS and Linux (`0600` files, `0700` directories it creates) and removes group and other access from ones an earlier sync installed; any replaced skill file keeps stricter permissions it had.
- Skills and plugins sync refuse paths that are not portable (a backslash, colon, control character, trailing dot or space, or a Windows device name) or that name one file on a case-insensitive host, and check each plugin file against its own plugin directory; `generate_manifest.py` and the skills overlay refuse such paths before publication. A plugin file or skill renamed only in case is no longer removed or retired, which on a macOS or Windows host would remove the published one.
- Skills sync updates the overlay history as one transaction under an OS lock, written through a temp file and an atomic replace.
- Fleet push, skills sync, and plugins sync share one destination path check. Plugins sync now also refuses a file path that leaves the plugin root, and all three refuse a dangling symlink among a destination's parent directories.
- Plugins sync records each staged plugin's check result on the host and runs a failed or missing check again, instead of reporting success on a rerun; a plugin whose re-check passes is reloaded. Files no longer published are removed from the staged plugin directory while unedited.
- Provider sync records a reload owed after a write and retries it on the next run; a retry that fails is `FAILED`, not a warning.
- Skills sync retires a skill it installed (per the host's sync record) once it is no longer published, keeping and reporting a locally edited one, and records an overlay hash only after a host accepts it.
- A failed shared preflight in `sync.py` stops the later scopes for that step's hosts.
- The skills, plugins, and client-config programs write through uniquely named temp files and rename one only while it is still the file they wrote.
- `cache-aware-autocompact` no longer lets two state stores in one process clobber one temp file or an old store write after a reload. Every store for a file shares one write queue; a newer store fences off older ones, and teardown waits for the write in flight.
- `cache-aware-autocompact`, `pm-native-worker-guard`, and `usage-limit-auto-resume` write their JSON state through one shared atomic writer, `plugins/_shared/atomic-json.ts`: a uniquely named, exclusively created temp file, flushed and renamed over the state file, with a brief retry when Windows reports the file busy. A temp file that cannot be removed after a failed write is reported with that write's error. The on-disk format is unchanged.
- Fleet sync clears an inherited `PASEO_HOST`, `PASEO_HOME`, and agent variables in every host program and provider reload, so a provider reload, a plugin install, and their config reads all address the host's own daemon, never one the launching session or a host's shell profile named. A host's optional `paseo_home` in `hosts.json` sets that daemon's home instead of the default.
- Fleet push copies only `hosts.json`, `paseo-providers.json`, `client-config.json`, and `global/AGENTS.md`; token files, pairing offers, backups, and other files in the fleet directory stay on the source host, a copy an earlier push left on a host is removed while unedited, and the push refuses to run while a `token_file` or `paseo_offer` resolves to one of the published files.
- Provider sync checks the host config and `required_env` before touching the Pi runtime, counts a Pi runtime change (or a runtime configuration that failed partway) as a write that owes a reload, and merges onto a config another writer changed during the merge instead of overwriting it.
- Client-config reads Codex TOML structure (headers with comments, array tables, quoted keys, multiline values) before merging and refuses, as `unsupported TOML, edit by hand`, a construct that could define, shadow, or duplicate a managed key path (an inline table, dotted key, or multi-line value at, inside, or over one; a table header at or under one; an array table at or over a managed section; a key outside a managed section that defines part of it) and a result with a managed key duplicated or outside its table; other keys and deeper tables in a managed section are left alone. Both client files are written through an fsynced temp file and renamed only while they still hold the revision the merge read; a concurrent change is merged in one retry, then the host fails.
- Provider and client-config backups get a unique name and are created new, so two updates in one second no longer overwrite the first backup.
- Pi deploy rollback checks every runtime file for edits, symlinks, and reparse points (junctions included) before changing anything, restores atomically, and checks the daemon config and backup again right before restoring the config; apply merges onto a daemon config changed during the install instead of overwriting it, and both stage the config through an unpredictable, exclusively created temp file and refuse a config that is not a regular file.
- The Pi picker patch replaces its state, bundle, entry, and backups atomically and remembers the previous patch generation, so an interrupted write can still be checked, reapplied, and rolled back.
- Provider sync fails a relay host's write with a readiness timeout, sending nothing, when its terminal shows no shell prompt.
- The fleet docs no longer promise a no-fleet single-host sync; a one-host fleet does that.
- Fleet sync's remote programs travel on stdin with their payload in one SHA256-checked envelope, so the ssh command line is a short fixed boot and Windows hosts stay far below the `cmd.exe` length limit; a corrupted envelope runs nothing.

### Added
- `wo` skill: how agents ask the owner questions, read short answers, and list open items. Claude Code and Codex use `/wo`; Pi uses `/skill:wo`.
- Skills sync installs package slash prompts for Pi and Codex with verified blobs, local-edit protection and retirement; Claude Code invokes user skills directly.
- `pi-fast-toggle`, a Paseo plugin with a per-agent composer pill that requests Fast on Pi agents whose model supports service tiers.
- OPC routes Pi Workers by task class. Code, code-bounded, test-fix, and automation start at Opus medium; reviews use Sol xhigh; browser uses Astra medium with Fast on; research is fixed at Luna xhigh; UI is fixed at Opus xhigh. Quota can raise an adjustable route but never lowers one; a `codexFallback` key in `routing.json` is accepted and ignored.
- OPC cloud lane: an owner toggle sends eligible editing lanes (`on`), or editing lanes and UI (`all`), to one Claude Code cloud session, always Opus 5.5 at xhigh on launch and follow-up, with an optional per-host cloud profile for a second claude.ai login that fails closed when unreadable. A dead cloud lane gets one local fallback Worker on its class route, the `ui` route for UI work.
- CI runs the repository tests on Ubuntu, macOS, and Windows, and plugin checks on Ubuntu and Windows.
- `cache-aware-autocompact` extends idle compaction to cold Claude-family recoveries and failed turns (`extendIdleCompaction`, default on).
- `pm-native-worker-guard`, a dry-run-first Paseo plugin that stops and archives native Codex or Claude Code agents created by a PM and tells the PM to use the Pi provider, with an owner allowlist.

### Removed
- OPC's direct native Codex CLI Worker (`worker.mjs`) and its `task.worker` record; a task file that still carries one is refused, and managed Paseo Workers are unchanged.

## 0.2.0 (2026-09-30)

### Fixed
- `cache-aware-autocompact` now restores idle compaction timers after restart or reload, preserves elapsed idle time with bounded overdue jitter, logs recovery counts, and uses durable checkpoints to prevent repeat sends.
- `cache-aware-autocompact` skips missing working directories before fetching recovery timelines, suppresses repeated per-agent recovery errors and unchanged recovery summaries, and reports unknown context usage as `context-unknown` while preserving terminal skip behavior.

### Changed
- `orphan-project-sweeper` now defaults to dry-run until `armed` is true, caps deletions per sweep (default 5), and provides a forced dry-run CLI, safeguard tests, and recovery instructions.

## 0.1.0 (2026-09-30)

First public release.

### Added
- 22 agent skills in six groups: engineering, orchestration, writing, research, web, and operations.
- Claude Code plugin marketplace (`claude plugin marketplace add Enjoyoer/loadout`) with six `loadout-*` plugins.
- Fleet sync (`sync.py`) for skills, Paseo plugins, Paseo provider pickers, and Codex and Claude Code settings, with SHA256 verification, local-edit protection, a private skill overlay, and `--migrate-path` for plugins.
- Four Paseo plugins: `usage-limit-auto-resume`, `merged-worker-archiver`, `cache-aware-autocompact`, and `orphan-project-sweeper`.
- An offline fleet sync demo (`examples/fleet_demo.py`), CI on Ubuntu and macOS, a contributing guide with a 7-day triage promise, a security policy, and a code of conduct.
- Skills adapted from Matt Pocock's skills and Context7 keep their upstream MIT licenses; see `THIRD_PARTY_NOTICES.md`.
